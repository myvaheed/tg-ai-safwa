## 1. Результат и критерии готовности

Thought — третий тип Card для сохранения мысли до её разбора. Его содержимое — Title, Note
и Blocked description. У Thought нет Stage, Priority, Schedule, Deadline, Effort, Time,
Categories, Energy, родителей, детей, Values, Tags и Checks. Служебные id, kind, даты и
version остаются обычными метаданными Card.

Встроенный Tag Inbox и все специальные правила по нему удаляются. Thought доступен независимо
от нового выключателя Profile; выключатель меняет только выбор типа при создании через Mutator.

Готовность подтверждают следующие наблюдаемые результаты:

1. Ручное создание и сохранённый AI proposal создают одинаковый Thought с тремя полями;
   неподдерживаемые изменения отвергаются доменом, а не только скрываются на экране.
2. Thought находится поиском, открывается по обычной ссылке Card и виден через Menu → Thoughts.
   Он не попадает в Backlog, Sprint, Today, Done, дерево Compass и рабочие расчёты.
3. Proposal создания имеет верхний ряд «Quality Plan» / «Direct Create» и нижний ряд
   Save / Discard. Первые две кнопки доступны также на сохранённом Thought.
4. Quality Plan открывает Blueprint с содержимым Thought. Direct Create передаёт Mutator
   запрос из Thought целиком: например, несколько Goals и Actions, а не одну выбранную сущность.
5. Нажатие любой из этих двух кнопок на proposal не сохраняет исходный Thought. Последующие
   изменения проходят обычные proposals и Save; Blueprint по-прежнему ничего не записывает.
6. Оба положения нового выключателя работают без перезапуска и сохраняются после него.
   Requests, Tags и изменение существующих сущностей следуют прежним правилам.
7. Существующие сценарии Goal/Action, очереди предложений, отмена, бюджеты и второй бот на
   shell проходят регрессионные проверки. Полный локальный набор, Ruff, архитектура и документация зелёные.

## 2. Подтверждённое поведение и предлагаемые значения

Владелец подтвердил: Direct Create исполняет запрос из Thought, включая несколько сущностей;
с proposal выбранный путь запускается вместо сохранения Thought; обе кнопки нужны после Save.

| Вопрос | Решение для реализации | Статус |
|---|---|---|
| Что создаёт Direct Create | Всё, что запрошено в содержимом, в пределах инструментов Mutator | Подтверждено |
| Несохранённый Thought при выборе пути | Не записывается; его review завершается | Подтверждено |
| Кнопки после Save | Обе доступны на экране Thought | Подтверждено |
| Режим Profile включён | Новые записи по умолчанию — Thoughts; Action/Goal/Value/Check только по явной просьбе | Подтверждено |
| Режим Profile выключен | Мысли, заметки и черновики захватываются как Thoughts; остальное создаётся обычным способом | Подтверждено |
| Исходное положение выключателя | Выключен, как Time tracking и Effort Points | Принято |
| Подпись выключателя | «Thoughts by default»; поле *thoughts_by_default* | Принято |
| Сохранённый Thought после запуска обработки | Остаётся до явного удаления; его kind не меняется | Принято при запуске реализации |
| Точная четвёрка кнопок на create proposal | Без дополнительной Edit; редактирование доступно после Save | Буквальное прочтение требования четырёх кнопок |
| Доступ к сохранённым мыслям | Отдельная кнопка Thoughts в Menu, старые первыми; без начального Request Thoughts | Уточнено владельцем |
| Оформление | Маркер «💭» в существующих местах отображения Card | Принято |
| Причина блокировки | Сохраняется и редактируется; сама не запускает рабочее уточнение Thought | Принято |

«Явная просьба» для выбора типа: пользователь называет Action, Goal, Value или Check, включая
обычные названия на своём языке; подтверждает типизированный план Blueprint; либо выбирает
Direct Create. «Запиши: купить молоко» при включённом режиме означает Thought. «Создай
Действие купить молоко» означает Action. Не добавлять классификатор или отдельную проверяющую модель.

Выключатель регулирует создание, не обсуждение: сообщение без просьбы что-либо сохранить
остаётся разговором. Он не превращает обновление существующей Goal в создание Thought.
Ручная кнопка Add сохраняет свой прежний начальный тип; Thought добавляется в выбор Kind.

## 4. Модель и доменная граница

Thought остаётся в features/cards и таблице cards. Новый feature-пакет, отдельная таблица,
новая система ссылок и параллельный путь сохранения не нужны.

1. Добавить *CardKind.THOUGHT*. Kind сохранённой Card остаётся неизменяемым. Обработка Thought
   создаёт запрошенные сущности обычным способом; не выполняет скрытую конверсию исходной Card.
2. Для Thought хранить `manual_stage`, `effective_stage` и `priority` как NULL; для Goal/Action
   сохранить действующие значения и проверки. Не подставлять фиктивный Backlog, Medium или Done.
   Эти три колонки становятся nullable в ORM; допустимость значений по kind обеспечивает домен.
   Учесть ORM defaults: переданный None не должен превращаться обратно в Backlog/Medium.
   Проверить именно повторное чтение сохранённой строки, а не только объект до flush.
3. Title обязателен; Note и `blocked_description` по существующему соглашению могут быть пустыми.
   Действующая нормализация текста и Markdown для Note и причины блокировки сохраняются.
4. У Thought остальные скалярные поля пусты, строки связей отсутствуют. Проверять ограничения
   на create/update и в отдельных операциях Stage, complete/reopen, Schedule, Priority и связей.
   Thought не может быть ни ребёнком, ни родителем. Проверить обратные входы связей.
5. Прямой вызов операции и устаревшая кнопка не должны обходить эти ограничения. Проверка
   происходит до изменения строки, записи события и обращения к Scheduler/Planning.
6. Удаление использует существующий путь Card. У Thought нет Done и автоматического архива;
   операция archive для него отвергается. Не менять правила удаления других Cards.
7. Save и ручной UI вызывают одни use cases, с session вызывающего и без внутреннего commit.
   Версия, аудит, workspace revision и обновление поискового индекса следуют существующим событиям.

Изменённые таблицы схемы: cards и user_profile. Таблицы связей по-прежнему общие, их схема
не меняется. Alpha-правило сохраняется: прямая правка ORM и снимка, без миграций и совместимости
со старой схемой.

## 5. Инструмент, чтение и рабочие выборки

Добавить инструмент *thought* в cards/agent.py по образцу `goal` / `action`: режимы create и
update; технический id для update; ровно три поля содержимого. Удаление — через `remove`.
Неподдерживаемых полей и режимов в схеме инструмента нет. Расширить roster Mutator и регистрацию
`mutation_tools` в существующем cards/module.py; proposal handler и presenter остаются Card.

Проверка правильного инструмента должна сравнивать точный kind, а не противопоставлять Action
остальным. Любая пара неверного инструмента и kind отвергается до review. Для Thought preparation
не запускает Scheduler, напоминание на новом item или проверки качества Goal/Action.

Расширить `ai_cards`, сохранив его имя, доступы читателей и поиск по title/note/blocked_description.
Thought читается с kind thought, без Stage и остальных неприменимых значений. Не создавать
дополнительный AI view только для этого типа.

Разделить места чтения по назначению, без глобального переписывания всех запросов:

- Поиск, Request по всем Cards, похожие items и открытие по ссылке должны видеть Thought.
  В `open_cards` явно включить Thought: сравнение NULL с Done этого не сделает.
- Home, Dashboard, Plan/Sprint, рабочий контекст Advisor, расчёт нагрузки и прогресса читают
  только соответствующие Goal/Action. Отсутствие Stage не заменяет проверку kind.
- В `workspace_context` и `close_items` не выдавать Thought за Goal и не прибавлять его к
  числу Goals. При прямом обращении к Thought использовать обычный поиск/чтение Card.
- В Compass явно выбрать Goal/Action вместо исключения Inbox. Thought не создаёт замечаний
  о Values, родителях или отсутствии Actions.
- Смешанный результат Request с Goal, Action и Thought отображается без ошибки сортировки,
  Stage или Priority. Не менять порядок Goal/Action ради нового типа.
- Уточнения Goal/Action и рабочие hooks не запускаются для Thought. Ограничить blocker follow-up
  Action, чтобы сохранение причины у Thought не превращалось в немедленный разбор.
  Onboarding получает правильный тип и не формулирует «Thought in Backlog».

## 6. Экраны и две кнопки запуска

В существующих creation/draft, screens, presentation и review добавить явную ветвь Thought.
Показывать Title, Note и причину блокировки. Сохранить существующие редакторы, Markdown,
цитаты, HTML-экранирование, возврат и правила одного живого экрана.

Create proposal Thought предлагает ровно четыре кнопки в двух рядах. Для него не предоставлять
Edit через `editable`; proposal обновления Thought использует обычную Edit для трёх полей.
Остальные create proposals сохраняют Edit. Подпись Save следует текущему общему правилу
действия, то есть «✅ Create»; отдельное переименование общего Save в этот план не входит.

Сохранённый Thought показывает «Quality Plan» и «Direct Create» перед обычными действиями
редактирования и удаления. Не предлагать Done, Reopen, Archive и рабочие связи.

Для кнопок review нужна одна небольшая декларативная возможность в существующем
`ProposalContribution`: feature предлагает подписи и callback-действия для подходящего
предложения. Shell рисует их через обычные `token_button`; обработчики объявляются через
`FeatureModule.callback_actions`. В эту же декларацию входит группировка двух кнопок в ряд.
Объявление cards предлагает их только одиночному create Thought. Без объявления поведение
и разметка review остаются прежними.

Не расширять `ProposalSwitch` запуском агентов: его контракт остаётся заменой одного вызова
перед Save. В общих пакетах не должно появиться названий Thought, Safwa, Blueprint или Mutator.
Новая возможность проверяется на втором боте без импорта Safwa.

### Переход с proposal

1. Под текущим foreground-владением проверить живой review, нужный kind/action и актуальность
   workspace. Изменившийся или истёкший review не запускает агента. Прочитать содержимое из
   подготовленного предложения, а не из исходного сообщения и не из текста Telegram.
2. Завершить review и оставшиеся неподтверждённые предложения по действующему правилу ухода
   со screen. Уже подтверждённые Saves записываются действующим механизмом очереди, все вместе.
   Сам Thought остаётся несохранённым. Ошибка записи ранее выбранных Saves не должна скрываться
   сообщением об успешном запуске; новый путь при такой ошибке не начинается.
3. Оставить честный итог очереди: что сохранено, что не сохранено и какой путь выбран.
   Не писать, будто нажатие Quality Plan было согласием сохранить Thought.
4. Записать выбранную инструкцию с полным содержимым через `send_owner_turn`, затем использовать
   `run_dialogue_turn`. Это тот же путь явного owner turn, который уже применяется после
   транскрипции; `ChatHost`, `TurnManager`, история и отмена остаются владельцами своих правил.
5. Quality Plan даёт Advisor явную просьбу вызвать `sub("blueprint")`. Direct Create даёт явный
   запрос исполнения для `route("workspace_mutator")`: Advisor выполняет только маршрутизацию,
   Mutator получает содержимое целиком и применяет обычные инструменты. Дополнительная проверка
   типа, пересказ содержимого Advisor и новый отдельный исполнитель не нужны.

Обычный `handle` после прерывания review может продолжить прежнюю цепочку. Не маскировать это
вызовом нового root для сброса бюджетов: возобновлённые сессии сохраняют счётчики; действительно
новые сессии получают свои. Quality Plan корректно завершает старую цепочку перед подсессией.
Проверить, что прежний Mutator не предлагает несохранённый Thought повторно.

### Переход с сохранённого Thought

Прочитать строку заново по id и проверить kind/существование под тем же владением ходом.
Передать текущие три поля тем же форматом owner turn и тем же путём исполнения. Исходный Thought
сохраняется; модель не получает инструкцию удалить его или изменить kind. Повторный запуск с
заново открытого экрана — новый явный запрос, без скрытой дедупликации результата.

Если сохранённый Thought открыт при действующей подсессии, сначала завершить её существующим
путём выхода с итогом, затем передать выбранную команду Advisor. Иначе `run_dialogue_turn`
отправит команду текущему агенту подсессии. Проверить оба действия в этом состоянии; вложенную
подсессию и второй параллельный разговор не вводить.

Оба входа используют одно построение команды в Telegram-адаптере cards. Callback содержит
id и выбранное действие; содержимое не копируется в token. Поля передаются раздельно с
сохранением Markdown и ссылок, без форматирования как исполняемого кода или системного промпта.
Внешнее HTML-экранирование не должно менять сохраняемые или передаваемые исходные слова.

## 7. Profile и короткие инструкции для SLM

Новое boolean-поле *thoughts_by_default* проходит те же model → enum → use case → proposal →
screen/review, что `time_tracking` и `effort_tracking`. Оно переключается вручную и через
Profile proposal. Значение для других features читается через profile/api.py.

Mutator перед каждым шагом читает Profile и выбирает одну инструкцию создания в системном промпте.
В `workspace_context` флажка нет. Для каждого положения промпт стабилен, перечень tools одинаков.
Проверки поддержки полей остаются кодом; выбор намерения — задачей Mutator.

### Точные предлагаемые тексты

Одно общее определение в cards/api.py, используемое в `ITEMS`:

> Thought: a captured note, idea or draft, with a Title, Note and blocked description.

Описание нового инструмента *thought*:

> Propose one Thought to keep for later.

Поле Note использует существующее правило `NOTE_REPLACED_WHOLE`. Поле причины — ту же короткую
формулировку, что у Action: слова пользователя; null при update очищает причину. Не копировать
в описание поля перечень всех запрещённых свойств: их нет в схеме инструмента.

Из описания Note инструмента `action` убрать указание использовать его для захвата мысли.
Оставить существующее правило `NOTE_REPLACED_WHOLE` после короткого начала:

> Details and how it supports its Values.

В Mutator заменить раздел Inbox следующими строками:

> Update existing items with their current type.
>
> Create Tags and Requests as requested.
>
> Direct Create or an accepted Blueprint plan: create every requested item with the type its content calls for.
>
Далее сервер выбирает ровно одну строку. При включённой настройке:

> Otherwise, create a Thought unless the user explicitly asks for an Action, Goal, Value or Check.

При выключенной:

> Otherwise, create the requested type; use a Thought to keep a note, idea or draft.

Уточнить существующую строку про новый Backlog: она относится только к новым Actions.
Существующие правила Effort относятся к Actions и не расширяются на Thought.

В Advisor заменить Inbox-правило одной строкой:

> Call `route("workspace_mutator")` to keep a note, idea or draft without asking for details.

Команда от кнопки Quality Plan, после которой следуют три поля Thought:

> Quality Plan. Plan this Thought with me. Open Blueprint.

Команда от кнопки Direct Create, после которой следуют те же поля:

> Direct Create. Carry out the request in this Thought. Create the items it describes.

Это команды интерфейса, записанные как выбор владельца, а не постоянно действующие инструкции
из содержимого Thought. Передавать также непустую причину блокировки; не трактовать её как
просьбу поменять блокировку всех создаваемых items.

В описании нового boolean-поля Profile:

> Whether new items default to Thoughts.

В onboarding заменить раздел Inbox коротким объяснением Thought, двух кнопок и выключателя.

## 11. Внесённая реализация

- Thought добавлен в существующий cards: свой инструмент, три поля, NULL Stage/Priority,
  общий Save, поиск, ссылки, ручной редактор и Menu → Thoughts. Рабочие операции и связи отвергаются.
- По уточнению владельца начальный Request Thoughts заменён отдельной кнопкой Menu.
  Новая база получает три обычных удаляемых Requests по отсутствующим прямым связям.
  Они игнорируют Done и архивные Goals, в том числе при проверке детей; завершённые Actions остаются детьми.
  Requests поддерживают Values; `ai_values.card_ids` позволяет точно проверять связь по id.
- Встроенный Inbox удалён вместе с установкой, защитой имени и исключениями по Tag.
  Его прежние проверки захвата перенесены на Thought; проверки Tags теперь подтверждают обычное поведение имени Inbox.
- Thoughts by default добавлен в Profile, его proposal, UI и выбор инструкции Mutator. Исходное значение — off;
  сохранённый Thought после запуска выбранного пути остаётся. Create proposal имеет четыре кнопки без Edit.
- Две кнопки используют обычные callbacks и owner turn. Проверены оба источника, оба положения
  настройки, несколько создаваемых items, сохранённая часть очереди, отклонённый хвост, повторный
  tap, устаревший review, ошибка ранее выбранного Save и переход из уже открытого Blueprint.
- Дополнительные кнопки объявляются через `ProposalContribution.actions`; независимый пример
  wallet проверяет общий механизм без импорта Safwa. Runtime, бюджеты и схема очереди не менялись.
- Снимок схемы меняет только cards и user_profile. Снимок промптов отражает Thought, новую
  настройку, исправленный каталог чтения и замену захвата через Inbox.
- Автоматические проверки не отправляют сообщения в Telegram и не вызывают живой провайдер.
  Работа реальной SLM и внешний вид клиента Telegram остаются отдельными opt-in QA-проверками.
- Замечания ревью исправлены: Thoughts имеет страницы по 25 с возвратом на исходную страницу
  и корректировкой страницы после удаления; общие промпты и onboarding ограничивают рабочие
  связи и завершение типами Goal/Action и перечисляют все три типа Card в Add.
