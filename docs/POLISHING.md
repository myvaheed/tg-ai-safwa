# Polishing

План по итогам двух аудитов и повторной проверки кода 2026-09-06, исходная версия — 60852a1.
Цель: обеспечить заявленные ограничения, закончить выделение shell и сократить объём чтения для изменения фичи.
Это план, а не выполненные изменения и не новая продуктовая спецификация. Согласованные сценарии сохраняются;
противоречия между ними требуют отдельного решения владельца, техническое исправление реализации — нет.

Исходный прогон: 882 passed, 3 skipped; Ruff проходит; архитектурный сканер — 238 модулей,
875 рёбер, 0 обнаруженных циклов и нарушений. Зелёные проверки не обнаружили перечисленные ниже ошибки.
Дополнительные воспроизведения использовали память или временную SQLite-базу с вымышленными данными, без сети.

Порядок: P1 — ошибки исполнения и рабочие данные; P2 — переносимость, проверки и навигация;
P3 — упрощение документации. Каждый пункт выполняется отдельно, с указанным критерием готовности.

архитектуры и метрик. Зависимые части доменного ядра не выдаются за независимо отключаемые плагины.

## Что из второго аудита не принято как обязательное изменение

- Переименовать один из foundation: различие уже задаётся пространством имён. Без измеримого выигрыша достаточно описать владение; массовое движение импортов отложено.
- Запретить because/since/so that: эти слова не делают правило непроверяемым; since может обозначать время. Проверять смысл сценария, не вводить лексический запрет.
- Один файл тестов на feature и падающий лимит 600 строк: смешивают уровни тестирования и поощряют деление ради цифры. Принято только разделение большого E2E-файла по ответственности.
- Удалить весь архив или все диаграммы «без риска»: сначала сохранить уникальные решения и обновить ссылки. Локальный каталог adapters с одним кешем не является отслеживаемым исходным пакетом и не требует отдельного рефакторинга.
- Считать default advisor сам по себе бизнес-зависимостью: это имя роли без выявленного условного поведения. Сначала устраняются ограничения типов, ключи связей, SQL и продуктовые строки.
- Автоматически проверить все имена всех докстрингов: нынешняя эвристика не различает реальную ссылку, пример и упоминание отсутствующего символа; такое расширение требует более узкого контракта.

Уточнения фактов второго отчёта: 21 файл feature, из них 17 Safwa и 4 shell; шесть исходных подпакетов
shell с инициализатором; 53 верхнеуровневых тестовых файла; у FeatureModule 15 полей-вкладов плюс name.
CLAUDE уже упоминает четыре файла shell — требуется уточнение области правила, а не добавление отсутствующей оговорки.

## Проверка при выполнении плана

Для ошибки сначала добавить воспроизведение, затем исправить её и запустить затронутый набор.
Перемещение тестов проверять сохранением случаев и параметризаций, изменение сборки — примером второго бота.
Полный набор выполнять после изменений исполнения или структуры; для документационного пункта достаточно проверки документов.

```powershell
rtk proxy uv run pytest -q
rtk proxy uv run ruff check .
rtk proxy uv run python scripts/architecture_metrics.py
rtk proxy uv run pytest tests/test_docs.py -q
```

Live Telegram остаётся отдельным явным запуском. Рабочая база, память и сессии не используются как тестовые фикстуры.
