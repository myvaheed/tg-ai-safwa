# Обновление сохранённых Реквестов

Одноразовый скрипт [upgrade_saved_requests.py](../scripts/upgrade_saved_requests.py)
добавляет тип результата к старым SQL, которые возвращали только ID Карточек.
Схему БД он не меняет. Запускайте его из каталога проекта с новой версией кода.

Остановите Safwa: скрипт берёт ту же блокировку БД, что и бот.
Укажите путь к существующей БД явно; пароль вводится скрыто в консоли.

~~~powershell
rtk proxy uv run python scripts/upgrade_saved_requests.py --database "E:\projects\tg-ai-safwa\data\safwa.db"
~~~

Это проверка без сохранения Реквестов. Если она завершилась успешно, примените изменения:

~~~powershell
rtk proxy uv run python scripts/upgrade_saved_requests.py --database "E:\projects\tg-ai-safwa\data\safwa.db" --apply
~~~

При другом расположении БД замените путь значением SAFWA_DATABASE_PATH.
Команда выводит ID и названия преобразуемых Реквестов.

Скрипт проверяет каждый SQL по существующим правилам чтения, добавляет item_type='card'
и сравнивает найденные Карточки и их порядок с прежней выдачей. Исходные условия,
ORDER BY, LIMIT и OFFSET остаются во вложенном запросе. Внешний порядок сохраняет
явно заданную сортировку; без неё экран продолжает использовать обычный порядок Карточек.

Все обновления сохраняются одной транзакцией. Если хотя бы один SQL не проходит проверку
или результат сравнения отличается, изменения Реквестов не сохраняются.
ID, названия, описания и выбранные фильтры Спринта сохраняются; версии Реквестов увеличиваются,
а обновления проходят через обычную операцию домена.
Реквесты, уже возвращающие item_type и id, проверяются и не переписываются.
Повторный запуск после успешного применения ничего не меняет.
